# Northlijn Server

Phase 1 of Northlijn's account system: signup, login, JWT access + refresh
tokens, and account deletion. Nothing else yet — no data syncs here. See
the iOS project's memory notes for the full phased plan (Phase 2 = sync,
Phase 3 = subscriptions).

## Local development

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
cp .env.example .env   # then edit DATABASE_URL and JWT_SECRET_KEY
```

Generate a real secret for `.env`:
```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

You need a real Postgres for local dev (matches production exactly):
```bash
# DATABASE_URL in .env, e.g.:
# postgresql+psycopg://northlijn:northlijn@localhost:5432/northlijn
./.venv/bin/alembic upgrade head
./.venv/bin/uvicorn app.main:app --reload
```

No local Postgres? The test suite runs against in-memory SQLite instead
(see `tests/conftest.py`) and needs no setup:
```bash
./.venv/bin/python -m pytest tests/ -v
```

## Deploying for free

This is what `render.yaml` in this repo is set up for right now. Costs
nothing, with one real tradeoff: Render's free web service tier sleeps
after 15 minutes idle, and the next request wakes it up with a ~30-50s
delay. Fine for solo dev/testing; revisit (switch `plan: free` to
`plan: starter` in `render.yaml`, ~$7/mo) once real users depend on this
not being slow on a cold start.

Render's *free* Postgres isn't used here — it auto-deletes after 30 days,
which isn't acceptable even for hobby data. Instead:

1. **Database**: sign up at [neon.tech](https://neon.tech) (free tier,
   doesn't expire) → create a project → copy its connection string
   (`postgresql://...`). Double-check Neon's current free-tier limits when
   you sign up, since these terms can change.
2. **App**: push this repo to GitHub, then on Render: **New → Blueprint**
   → connect the repo. It reads `render.yaml` and creates the web service
   only (no database, since `DATABASE_URL` is marked `sync: false` in the
   blueprint).
3. On the new service in Render's dashboard → **Environment**, paste your
   Neon connection string as `DATABASE_URL`. (The app automatically
   rewrites a bare `postgres://`/`postgresql://` URL to use the `psycopg3`
   driver, so paste it exactly as Neon gives it to you.)
4. `JWT_SECRET_KEY` is generated by Render itself — nothing to do here.
5. Run `alembic upgrade head` once against the database before the first
   request hits `/auth/signup` — Render dashboard → the service → **Shell**
   tab.
6. Confirm `GET /health` returns `{"status": "ok"}` before pointing the
   iOS app at it. The very first request after any idle period will be
   slow (cold start) — that's expected on the free tier, not a bug.

## Deploying for real (paid, once this has actual users)

Switch `plan: free` → `plan: starter` for the web service in
`render.yaml`, and add a `databases:` block back for a Render-managed
Postgres (or keep Neon and upgrade its plan instead) — removes the
sleep/cold-start behavior. Budget roughly $7-14/month depending on which
pieces move to a paid tier.

## Endpoints

| Method | Path            | Auth required | Notes |
|--------|-----------------|---------------|-------|
| POST   | `/auth/signup`  | no            | 201 + token pair, or 409 if email taken |
| POST   | `/auth/login`   | no            | 200 + token pair, or 401 (generic message) |
| POST   | `/auth/refresh` | no (refresh token in body) | Rotates the refresh token |
| POST   | `/auth/logout`  | no (refresh token in body) | Idempotent |
| GET    | `/users/me`     | yes (Bearer access token) | |
| DELETE | `/users/me`     | yes (Bearer access token) | Required by Apple Guideline 5.1.1(v) |
| GET    | `/health`       | no            | Liveness check for Render |
